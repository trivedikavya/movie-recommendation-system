# CineMind — Movie Recommendation Web App (Part B)

A Next.js + TypeScript web app that serves the recommender trained in the Part A notebook
(`../notebooks/DMW_Recommender.ipynb`). No Python runs in this app at all -- the trained model
was exported to plain JSON files (`model-data/`) once, and every recommendation is computed by
a TypeScript port of the same Hybrid scoring logic validated in the notebook.

## Stack

- **Next.js 16** (App Router) + **TypeScript**, Tailwind CSS v4 (dark theme)
- **Postgres** (Neon / Vercel Postgres) via **Prisma 6**, using the Neon serverless driver
  adapter (connects over HTTPS/WebSocket, not raw TCP -- avoids exhausting Postgres' connection
  limit on serverless platforms)
- Custom auth: bcrypt password hashing + a signed JWT session cookie (no external auth library)
- Recommender: `lib/recommender.ts`, reading `model-data/*.json`

## Project layout

```
web/
  app/                    pages (login, signup, onboarding, home, browse, movie/[id], profile)
    api/                  route handlers (auth, recommendations, interactions, movies, genres, me)
  components/             MovieCard, MovieRow, MoviePoster, TopBar, GenreChip, LikeButton, RatingStars
  lib/
    recommender.ts        the ported Hybrid scoring logic (cold-start + personalised)
    model-data.ts          loads model-data/*.json once, caches in memory
    auth.ts, db.ts, validation.ts, interaction-weight.ts, api-client.ts, poster-gradient.ts
  model-data/              movies.json, similarity_topk.json, popularity.json, rules.json, genres.json
                           (generated by ../scripts/export_model.py -- do not hand-edit)
  prisma/
    schema.prisma          User, Interaction models
    seed.ts                creates the demo/demo123 account
    migrations/             SQL migration history
  public/posters/          OPTIONAL manual poster images -- see public/posters/README.md
  scripts/
    apply-migration.mjs     dev-only helper, see "Local DNS quirk" below
```

## Setup

1. **Install dependencies** (this project uses pnpm):
   ```
   pnpm install
   ```

2. **Get a Postgres database.** Easiest options, both free:
   - [Neon](https://neon.tech) -- sign up, create a project, copy the connection string.
   - [Vercel Postgres](https://vercel.com/storage) -- from your Vercel dashboard, Storage tab.

3. **Create `web/.env`** (copy `.env.example`) and fill in:
   ```
   DATABASE_URL="postgresql://...your connection string..."
   JWT_SECRET="<generate with: node -e "console.log(require('crypto').randomBytes(32).toString('hex'))">"
   LOCAL_DNS_FIX="false"   # see note below -- only set true if needed
   ```

4. **Run the database migration and seed the demo account:**
   ```
   pnpm exec prisma migrate deploy
   pnpm exec prisma db seed
   ```

5. **Run the dev server:**
   ```
   pnpm dev
   ```
   Open http://localhost:3000. Log in with the seeded demo account (`demo` / `demo123`), use
   "Continue as Guest", or sign up a new account.

## Regenerating the recommender data

If you change anything upstream in the Part A notebook (new ratings, retrained model, etc.),
regenerate the JSON the web app reads:
```
python ../scripts/export_model.py
```
This overwrites `model-data/*.json` from the current `../artifacts/*.joblib` files. No restart
of the Next.js app is needed beyond a normal reload (the files are read fresh per server
process, cached after first read).

## Poster images (optional, manual)

This app does not call any external image API. See `public/posters/README.md` for the exact
convention (drop a `<movieId>.jpg` or `.png` file into `public/posters/`). Movies without a
manually-added image show a dark gradient card instead, which is the permanent design, not a
placeholder.

## A local-network DNS quirk (probably not relevant to you)

While building this app, the developer's local network's default DNS resolver failed to
resolve Neon's long compute hostnames (confirmed Google's `8.8.8.8` resolves them fine). If
`prisma migrate dev`/`db seed`/the app itself can't reach your database but the connection
string is definitely correct, set `LOCAL_DNS_FIX="true"` in `.env` -- this makes the app route
DNS lookups through `8.8.8.8`/`1.1.1.1` instead of your network's default resolver
(`lib/fix-local-dns.mjs`, wired in via `instrumentation.ts`). This is never needed on Vercel.

## Deploying to Vercel

1. Push this repository to GitHub.
2. In Vercel: **New Project** → import the repo → set **Root Directory** to `web`.
3. Add a Postgres database via Vercel's Storage tab (auto-sets `DATABASE_URL`), or paste your
   own Neon `DATABASE_URL` as an environment variable.
4. Add the `JWT_SECRET` environment variable (same value or a freshly generated one).
5. Deploy. Then run the migration once against the production database:
   ```
   DATABASE_URL="<production url>" pnpm exec prisma migrate deploy
   DATABASE_URL="<production url>" pnpm exec prisma db seed
   ```
6. Visit your Vercel URL -- log in with `demo`/`demo123` or sign up.

## Demo / guest accounts

- **Demo account:** username `demo`, password `demo123` (seeded, persists like any real account
  -- useful to show recommendations improving across multiple logins).
- **Guest:** click "Continue as Guest" on the login page -- creates a fresh, ephemeral account
  instantly, no typing required, skips the genre-picking onboarding screen.
